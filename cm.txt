fix(LAB-4189): budget the claim cap by unreserved keys and truncate the ingested representative claim

Two real defects, both mine, both in the bound added earlier in this branch.

The cap counted the whole map while `bound_ingested_claims` counted only
unreserved keys, so the two paths disagreed about the same bound and the live
one was the stricter. An account carrying all five reserved keys admitted 27
unknown claims, not the documented 32. `claim_admitted` now counts unreserved
keys, so live admission and whole-map ingest agree and the documented 32 + 5
holds on both.

`representative_claim` was truncated on the header path only. The two sites that
assign the claim map whole — the persisted state file and the cross-replica
mirror — stored it raw, while `bound_ingested_claims` truncated the keys beside
it. `metrics_gate_weight` looks that string up in the map, so a long claim
restored from either path missed its own entry and fell through to the general
claim or the max-waste_risk branch: the routing-weight gauges then reported a
different claim than the router used. Same defect the header path was fixed for,
left open on the paths that bypass it.

Both mutation-verified: restoring either old line fails its test.
